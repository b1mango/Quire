# 卷帙 Quire 重构方案（2026-11-12）

> 状态：**待审批**。原型 `prototype.html`（单文件、零外链、假数据，双击即开）。本文档 + 原型是方案，不是实施完成报告；生产代码未改动。

## 0. 结论

1. **活板（huoban）**：值得借，不值得整体并入。借 4 样：广告/水印清洗规则 + 删除账单、EPUB 排版 CSS 与元数据、字体子集化、文字封面；另立新功能「导入本地 TXT/EPUB」时可把活板作为固定版本的可选依赖。
2. **UI**：保留后端 API、零构建原生 JS、本地服务架构不动，前端整体重构为「一个输入框 + 书架 + 任务 + 设置」四块，外观从 4 套主题收敛为 1 套设计语言（浅/深/跟随系统 + 3 种强调色）。

## 3. 新设计

### 3.1 原则

- **书是主角，界面退后**：只有书封有颜色，界面本身用中性色。暖色只出现在内容（书封）和强调色上，不铺满整个界面——避开「米色底 + 衬线 + 陶土色」这种模板化配方。
- **系统先判断，用户再确认**：类型、单章/目录、续抓起点都由 probe 判断，用户只在需要时改。
- **一个屏幕一个焦点**：采集页焦点是输入框，书库是书封，任务页是进度。
- 动效只用来表达状态变化；完整支持减少动态效果（reduced-motion）。

### 3.2 信息架构

```
侧栏（全高，红绿灯区兼拖拽）
├─ 采集          ⌘N   ← 一个输入框；推荐站点、导入本地文件并入空态
├─ 书库   9      ⌘1
├─ 任务   (徽标) ⌘2   ← 真正的队列
├─ 书架：有更新 / 追更中（智能分组）
├─ 分组：修仙 / 漫画 …（可拖书进来；＋新建）
└─ 底部：进行中任务迷你卡 + 设置 ⌘,
全局：⌘K 命令面板（搜书 / 跳转 / 粘贴链接即采集）；任意处 ⌘V 链接直接识别
```

删除：顶栏、推荐站点导航项、主题按钮组、文件夹卡片。

### 3.3 页面

**采集**

- 空态：居中标题「收一本书进来」，下面是大输入框，次级入口「导入本地 TXT / EPUB…」，再往下是「从这些站点找书」6 张卡片。
- 识别时：输入框下方用三个真实阶段点（连接站点 → 读取目录 → 抽样估算体积）显示进度，不显示假百分比。
- 识别结果：一张「书的预览卡」，包含：
  - 封面、书名、作者、站点、章数、状态；
  - 类型标签（可点击改成漫画）；
  - 书库已有时给出绿色提示「已有第 1–380 章，默认从 381 续抓」；
  - 选项行：章节范围、格式（多选）、版式（3 张可视预览卡）；
  - 「更多选项」折叠：分卷、图片正文 OCR、清洗开关。
- 底部悬浮条：实时摘要「第 381–412 章 · 32 章 · EPUB · 宋体 · 约 141 KB」+ 「开始采集 ⌘↵」。
- 识别失败：说清原因，并给出「只抓这一章 / 查看页面快照」。

**任务**

- 左列分「进行中」和「最近」两组；右侧显示详情：书封、阶段文案、进度条、四个数字。
- 漫画保留原设计的签名元素：逐页缩略图边下边长（显影动画）；缺页用虚线占位，并提供「补抓缺页」。
- 小说的章节列表：当前章置顶，接着是已完成（倒序），最后一行「还有 N 章等待下载」。
- 失败时给出人话原因和对应恢复入口，例如 403 → 打开网络设置。
- 空态：「没有任务」+「去采集」。

**书库**

- 工具条：搜索（⌘F）、封面/列表切换、检查更新（按钮内显示进度）。
- 封面格支持单选、⌘ 多选、Shift 连选、⌘A 全选、方向键移动、回车打开、Esc 取消选择。
- 选中后右侧滑出检查器：
  - 大封面，「打开 / 在 Finder 中显示」；
  - 有更新时显示「来源新增 32 章 · 续抓」；
  - 来源、章节、加入时间、分组；
  - 文件列表（每个格式各一行，可点击打开）、重新导出；
  - 追更开关、移动到分组、检查更新、删除。
- 多选时检查器变为批量面板（叠放的书封 + 批量操作）。
- 删除确认写清后果；删除和移动都可以撤销（Toast）。
- 空态分三种：空书库 / 搜索无结果 / 空分组。

**设置**：分组列表的写法，标签在左、控件在右。

- 改动即保存，工具条右上角短暂显示「已保存」，不再有保存按钮。
- 分区：外观（明暗卡片 + 强调色）/ 输出 / 网络 / 文字识别 / 追更 / 关于。
- 「使用真实浏览器」打开后才显示 CDP 地址（渐进展开）。

### 3.4 视觉语言「书斋」

- **签名元素：题签式书封**。没有真实封面时，生成线装书样式：布纹底色从 10 种传统色中按书名散列取一个（靛青、黛绿、绛、藏蓝、赭……）；左上角一张米白纸签竖排宋体书名，作者竖排在左下，右侧画订线针脚。书名按字数自动调字号，西文书名改为横排纸签。同一套版式同时用作 EPUB 封面（H4），书库和导出文件就能保持一致。
- **令牌**（浅 / 深两套同时设计）：

| 令牌 | 浅 | 深 |
|---|---|---|
| bg / sidebar / surface | `#F7F6F3` / `#EFEDE8` / `#FFFFFF` | `#151413` / `#1B1A18` / `#211F1D` |
| text / text-2 / text-3 | `#1D1B18` / `#5C574F` / `#767065` | `#EDEAE4` / `#AFA89D` / `#8F897F` |
| 强调 朱砂（默认） | `#B0402F`（白字 5.9:1） | `#C9513D`，文字用 `#F08A74` |
| 强调 青黛 / 墨 | `#2F5D8A` / `#1D1B18` | `#3F72A6` / `#EDEAE4` |
| line | 9% 黑 | 8% 白 |
| 圆角 | 控件 6、面板 10–14、书封 2/4 | 同 |

- **字体**：界面用 PingFang SC，13px 基准（贴近 macOS 原生密度）；宋体只用于书名和内容。数字统一 `tabular-nums`，不再用等宽字体显示元信息。
- **主题收敛**：纸感、暗房·浅、暗房·深、瑞士网格 → 明暗（浅/深/跟随系统）× 强调色（朱砂/青黛/墨）。这是推翻设计 §3.3「4 主题冻结」的决策，**需要你拍板**。旧设置迁移规则：paper → 浅 + 朱砂，darkroom:dark → 深 + 青黛，darkroom:light → 浅 + 青黛，swiss → 浅 + 墨。

### 3.5 不变的

- 后端 API、SSE、token 鉴权、WKWebView 壳都不变。新增的少量接口单独列出：任务列表已有 `GET /api/jobs`，只需前端多任务化；检查器里的「重新导出」复用 `reassemble`。
- 零构建、零外链、前端 < 200 KB、原生 JS。
- 已有的键盘与可访问性成果（aria-pressed、live region、dialog/popover）沿用。
